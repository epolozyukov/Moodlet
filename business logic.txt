🎮 Moodlet — Game Logic Reference (as implemented)
Last updated: 2026-02-25

═══════════════════════════════════════════════════
1. CORE STATS (0–100 scale)
═══════════════════════════════════════════════════

Stat        Meaning              Direction
─────────── ──────────────────── ────────────────────
Hunger      Fullness level       Higher = better (100 = full, 0 = starving)
Hygiene     Cleanliness          Higher = better
Energy      Rest level           Higher = better
Happiness   Mood / wellbeing     Higher = better
Health      Physical health      Higher = better (starts at 100)

NOTE: Hunger is stored as "fullness" (inverted from classic Tamagotchi convention).
      A pet at hunger=0 is starving; hunger=100 is completely full.

All values are clamped between 0 and 100 at all times.

═══════════════════════════════════════════════════
2. TIME MODEL
═══════════════════════════════════════════════════

The game uses continuous elapsed-time decay, not discrete ticks.
Decay rates are expressed as "ms per 1 point of change".
This allows accurate offline time processing on every app open.

A UI tick fires every 10 seconds to refresh the display.
Sickness tracking uses a 5-minute tick equivalent for the 3-tick threshold.
Offline decay is resolved in full on each session start.

═══════════════════════════════════════════════════
3. NATURAL DECAY RATES
═══════════════════════════════════════════════════

Awake decay (per point):
  Hunger (fullness):  −1 per 75s    (equivalent to −4 per 5 min)
  Energy:             −1 per 150s   (equivalent to −2 per 5 min)
  Happiness:          −1 per 150s   (equivalent to −2 per 5 min)
  Hygiene:            −1 per 100s   (equivalent to −3 per 5 min)
  Health:             −1 per 75s    CONDITIONAL only (see below)

Sleeping decay (per point):
  Energy:             +1 per 33s    (equivalent to +9 per 5 min — gains while sleeping)
  Hunger (fullness):  −1 per 300s   (equivalent to −1 per 5 min — still gets hungry, slowly)
  Happiness:          −1 per 150s   (same rate as awake)
  Hygiene:            no decay while sleeping

Happiness extra penalties (stack on top of base decay):
  Hunger < 20 (near starving):   extra −1 per 150s
  Hygiene < 30 (dirty):          extra −1 per 150s

Health decay — active when ANY condition is true:
  Hunger = 0 (starving)
  Hygiene < 20 (very dirty)
  Energy = 0 (collapsed)
  isSick = true

When actively sick, additional decay per pass:
  Happiness: extra −1 per ~100s (approximately −3 per 5 min)
  Health:    extra −1 per 75s   (approximately −4 per 5 min)

═══════════════════════════════════════════════════
4. SLEEP RULES
═══════════════════════════════════════════════════

Auto-sleep trigger (fires each decay pass when awake):
  Energy ≤ 15    → forced sleep immediately
  Energy < 20    → 20% random chance to fall asleep

While sleeping:
  Energy gains, hunger drops slowly, happiness drops at normal rate
  Hygiene does not decay
  Cannot use Meal, Snack, Play, Chat
  "Wake Up" button replaces all other action buttons

Wake conditions:
  Energy ≥ 90   → auto-wakes
  User clicks "Wake Up" button → manual wake (happiness −5 grumpy penalty)

Cross-session sleep resolution:
  On app open, if pet was sleeping, the engine calculates whether energy
  would have reached 90 during the gap. If yes, it wakes the pet at the
  correct point and applies post-sleep awake decay for the remaining time.

═══════════════════════════════════════════════════
5. USER ACTIONS
═══════════════════════════════════════════════════

Meal
  Hunger +35 (capped at 100)
  Hygiene −8
  Happiness +4
  If hunger was already > 80 (very full): happiness −3 overfeeding penalty
  Net happiness change when full: +1

Snack
  Hunger +15
  Happiness +8
  Health −3 (junk food penalty)

Play
  Allowed only if: energy > 20 AND not sleeping AND not sick
  Happiness +20
  Energy −10
  Hunger −6 (burns energy = gets hungrier)

Clean
  Hygiene → 100 (instant full clean)
  Happiness +3

Sleep
  Sets isSleeping = true, starts sleep timer
  Energy recovery via decay engine (+1 per 33s)
  All action buttons disabled (only Wake Up shown)

Wake Up (manual)
  isSleeping = false
  Happiness −5 (grumpy penalty)

Medicine  (visible only when isSick = true)
  Health +25
  isSick = false, sicknessTicks = 0, sicknessStart = null
  Happiness −2 (unpleasant)

═══════════════════════════════════════════════════
6. SICKNESS RULES
═══════════════════════════════════════════════════

Sickness condition is active when ANY of:
  Hunger < 10    (nearly starving; maps to classic "hunger > 90")
  Hygiene < 15   (very dirty)
  Energy = 0     (completely exhausted)
  Happiness < 10 (deeply unhappy)

Sickness tracking:
  Each decay pass, elapsed time is converted to 5-min tick equivalents.
  If the condition is active: sicknessTicks += tickEquivalents
  If sicknessTicks ≥ 3 and not already sick: isSick = true
  If condition clears and not yet sick: sicknessTicks resets to 0

Once sick (isSick = true):
  Additional happiness and health decay applied every pass
  Play is disabled
  sicknessTicks is NOT reset (only Medicine clears the sick state)
  sicknessStart timestamp is recorded for death tracking

Clearing sickness:
  Only Medicine clears isSick. Stats recovering does not.

═══════════════════════════════════════════════════
7. GROWTH / EVOLUTION
═══════════════════════════════════════════════════

Stage progression (time in current stage → advance):
  Egg   → Baby   after  1 hour
  Baby  → Child  after 24 hours
  Child → Teen   after 48 hours
  Teen  → Adult  after 72 hours
  Adult → (final stage, no further advancement)

Stages are tracked via `stage` and `stageStartTime` fields.
Advancement is checked every decay pass.
Each stage uses a different AI personality voice and sprite emoji.

Care Score
  Updated every decay pass as a weighted rolling average:
    tickScore = average of:
      (hunger ≥ 40) ? 1 : 0       — pet is at least reasonably fed
      (happiness > 50) ? 1 : 0
      (hygiene > 50) ? 1 : 0
      (!isSick) ? 1 : 0
    careScore = (prevCareScore × 0.9) + (tickScore × 10)

  Range: 0–100. Higher = better care.
  Currently tracked but not yet used to gate evolution outcomes.
  (Future: score ≥ 80 → best character, 50–79 → normal, < 50 → bad ending)

═══════════════════════════════════════════════════
8. DEATH CONDITIONS
═══════════════════════════════════════════════════

Pet dies (isDead = true) if ANY of:
  health = 0
  isSick AND sicknessStart > 12 hours ago
  hunger = 0 continuously for > 30 minutes   (hungerCriticalStart tracked)
  lastUpdated > 72 hours ago                  (user neglect)

On death: death screen shown with stage reached and care score.
User can "Start Over" (clears localStorage, triggers name modal).

═══════════════════════════════════════════════════
9. ATTENTION ALERTS
═══════════════════════════════════════════════════

Alert fires when ANY threshold is crossed:
  Hunger < 30    (pet is getting hungry)
  Energy < 30    (getting sleepy)
  Hygiene < 40   (getting dirty)
  Happiness < 40 (getting sad)
  isSick = true

Cooldown: minimum 10 minutes between alerts.
lastAlertTime is saved to state and persists across sessions.

Alert effect: sprite pulses for 3 seconds in the UI.

═══════════════════════════════════════════════════
10. MOOD LABEL (for UI and AI)
═══════════════════════════════════════════════════

Mood is derived directly from the Happiness stat:

  happiness ≥ 60  → "happy"
  happiness ≥ 40  → "neutral"
  happiness ≥ 15  → "sad"
  happiness < 15  → "critical"

Used to select fallback AI messages and sprite border style.

═══════════════════════════════════════════════════
11. STREAK TRACKING
═══════════════════════════════════════════════════

currentStreak increments by 1 each day the app is opened.
If a full calendar day is skipped, streak resets to 1.
lastVisitDate is compared to yesterday's date on each load.

═══════════════════════════════════════════════════
12. CHAT (AI)
═══════════════════════════════════════════════════

Uses Groq API (llama-3.3-70b-versatile primary, llama3-8b-8192 fallback).
System prompt includes: name, stage, all 5 stats, mood, isSick, lastUserAction.
Pet AI personality adapts to stage (egg = barely conscious → adult = wry/dry).
Responses capped at 40 words, no markdown, no emojis.

Chat history: last 10 messages (5 exchanges) stored in localStorage.
Rate limit: max 1 request per 5 seconds per session (in-memory, server-side).
On rate limit or API failure: in-character fallback message returned.

Chat is disabled when isSick or isSleeping.

═══════════════════════════════════════════════════
13. STATE PERSISTENCE
═══════════════════════════════════════════════════

Full PetState is stored in localStorage as JSON (key: "moodlet_pet").
On load, old saves missing new fields are migrated by spreading defaults.
Session ID for rate limiting stored in localStorage (key: "moodlet_session").
